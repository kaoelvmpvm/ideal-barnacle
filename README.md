以 [Math Analyze](https://github.com/kaoelvmpvm/Math_analyze) 的自適應出卷與學習分析架構為基礎，獨立製作的理化版本。

## 首次使用

1. 開啟 [GitHub Pages 設定](https://github.com/kaoelvmpvm/ideal-barnacle/settings/pages) → Build and deployment → GitHub Actions。
2. 到 [Physics Analyze 網站](https://kaoelvmpvm.github.io/ideal-barnacle/)。
3. 從教師與 ChatGPT 的交付對話下載「PhysicsAnalyze_508題_原版PDF裁切題圖包_v1.zip」，**不要將題圖包上傳到公開 GitHub**。
4. 到「設定與備份」→「匯入本機題庫 ZIP」匯入題圖包；首次匯入後，才會顯示題庫及可出卷功能。
5. 建立匿名學生代號、選擇單元和自行指定訓練日期，產生試卷／批次個別卷；測驗後可登記答錯、空白及錯因。
6. 每次完成登記後下載 JSON 備份；換瀏覽器需另外重新匯入題圖 ZIP。

## 功能

- 個人與班級共用卷，教師自由選擇訓練日期，預設 15 題，可設定 4～45 題及 15／25／45 分鐘。
- 延用 Math Analyze v9 自適應選題：優先補強錯誤單元、擴大未測涵蓋、避開近期重複（7 日內選過／14 日內已確認答對），題庫不足時說明放寬。
- 題目卡片保留原版 PDF 的光學圖、波形圖、實驗示意與選項；原卷的括號答案標示已從題圖遮蔽。
- 錯題／空白登記、錯因分析、學習進度、批次個別卷合併 PDF、教師答案 CSV、備份還原。
- 分析僅能診斷這**八個單元的表現**，不可宣稱已完成更細的理化概念診斷。
- 全部運行於瀏覽器（IndexedDB + localStorage），沒有後端、帳號系統或教師跨裝置即時監控。

## 題目品質與隱私限制

- **508 題的題號、出處、來源答案標記已從教師提供的八份 PDF 結構化抽取，並產生 508 張 WebP。**
- 題圖切割與檔案完整性可自動檢查；**各題答案、跨頁圖形及複雜公式仍需教師抽查，不應將來源答案等同獨立驗算。**
- 使用的 ZIP 版本：`physics-v1-native-pdf-crops`。
- 此公開儲存庫不包含有版權的原題圖或學生資料。題包應限於有合法使用權的教學用途。
- 不建議使用學生真實姓名；清除站點資料或更換電腦前應備份紀錄。


## 固定兩頁自動配題（2026-10-28）

開啟網站的「**雙頁配題**」分頁。頁面與答案模式已固定，仍可設定：

- **強制 A4 恰好兩頁（含答案）**，不再選擇頁數；**省紙答案固定於第二頁底端**，不另外增加答案頁。第二頁含教師答案，不宜直接發給學生。
- 期望題數 1～45 題，並可設定「至少幾題」；若紙張容量不足，會自動減少非必要題，而**不縮到無法閱讀、不切掉圖形或選項**。無法符合最低題數時停止生成。
- 八個單元的勾選、個別單元最低題數；亦可切換到**精確題數模式**（例如 3-1 恰好5題、4-4恰好3題）。精確模式下，以單元填入數字的總和作為必要題數，放不下就提示調整。
- 全班共用／指定學生、訓練日期、時間、試卷標題；候選題由原版自適應選題引擎根據過去作答資料排序，再參照原題圖片高度安排紙張。

出卷後下載 **包含末頁答案的 A4 PDF**；該卷也記錄到「智能出卷」歷次試卷，能從原介面再次下載固定版面 PDF、取得答案 CSV，並在「錯題登記」中繼續使用。

**注意：**系統固定輸出兩頁（第二頁可能留白），選題依題圖寬高決定版面，優先完整保留題目。來源答案未全面獨立驗證。此功能沿用原本的理化 v1 ZIP，**不需重新匯入題圖包**；不更動既有學生、測驗與錯題歷史。

自動回歸測試：`node tests/fixed-pages.test.cjs`，涵蓋固定兩頁省紙模式、舊版一至多頁相容、無重複題、版面不重疊以及衝突條件阻擋。瀏覽器實際列印效果仍建議教師試印確認。


## v2｜個別卷自動帶入學生代號與題圖尺寸補強（2026-10-20）

- 「錯題登記」選個別卷時，學生代號直接切換為該卷設定的學生。切到全班共用卷則維持手動選擇，教師仍可修改其他既有學生的紀錄。
- 固定頁數配題會優先使用 catalog.json 的題圖尺寸；如果舊題包缺少尺寸欄位，直接從本機 WebP 讀取尺寸，避免錯誤估算或因缺欄位無法配題。
- 自動測試包含 A4 頁數與答案排版、個別卷學生綁定。既有 508 題 v1 題包、學生資料與歷次試卷不需重置。

## 合併 PDF 下載修復（2026-10-28）

批次個別卷合併時會先在瀏覽器本機產生 PDF Blob，並顯示檔案頁數與大小。若瀏覽器阻擋非同步自動下載，可在「批次個別卷」操作區點選「點此下載合併 PDF（若未自動下載）」手動取得檔案。若生成失敗不會誤顯示下載成功，會保留錯誤訊息供檢查。本機題圖、紀錄不會上傳。

## 批次個別卷固定雙頁（2026-10-28）

- 「智能出卷 → 批次個別卷」的**新生成試卷**強制每位學生 **A4 恰好 2 頁**，題目可跨兩頁；教師答案固定在每位學生第 2 頁底端（省紙），**不是另加一頁**。合併檔案總頁數必須等於學生人數 × 2。
- 先依每位學生的自適應排序選取候選題，再依原圖尺寸排入兩頁。容量不足時會**在儲存前**減少該學生題數，批次歷史會顯示實際題數範圍；絕不先儲存更多題、PDF 再暗中刪題。不能完成整批兩頁版面時取消整批建立。
- 每位學生的原題編號、固定頁面配置與實際列印順序一起保存，供「錯題登記」、個別診斷與日後重新下載使用；原始題庫、已存在的學生、舊卷紀錄不會被覆寫。
- 「合併已建立的個別卷」與舊版批次重印也遵守兩頁輸出；舊卷如果全部題目無法容納兩頁，會明確拒絕重排，不會裁切、省略或調換已保存的題號。原紀錄保留，請重新產生新的雙頁卷。
- 第二頁含答案，對外發放前務必由教師檢查；此功能不會將學生資料或題圖上傳至 GitHub。

## 2026-10-28：修復批次合併 PDF 題圖尺寸不一致

- 修復「學生 815-01 題目 P31-017 圖片尺寸變動，停止輸出」類型錯誤：原批次配題信任題庫索引中的 image_width / image_height，實際轉 JPEG 時則以 WebP 解碼尺寸計算，兩者不一致會錯誤中止。
- 新批次一律從瀏覽器本機原始 WebP 解碼，按照 PDF 圖像縮放比例與像素取整方式測量尺寸；再進行每人固定兩頁含底端答案的配題。題庫索引內的尺寸不再用於批次版面決策。
- 已儲存的舊批次重新合併時，先驗證真實尺寸；有差異就以同一題目順序完整重新排版，不改動歷史試卷與錯題紀錄。若舊試卷所有題目無法容納兩頁，會明示重新產生新雙頁卷，而不是強制縮圖、裁切或刪題。
- 一般固定頁數出卷及重印同樣改成實際讀取原始題圖尺寸，避免再次發生相同不一致。
- 測試：`node tests/fixed-pages.test.cjs` 及 `node tests/batch-geometry.test.cjs`。第二項以刻意不一致的模擬題庫索引尺寸，驗證兩頁配題、每人第2頁答案、合併PDF頁數及舊版面修復。實際使用者端的 ZIP 題包及瀏覽器下載仍需現場測試。

## 2026-10-28：批次 PDF 題圖尺寸錯誤的根因修復

- 根因：早期 `features.js` 的 `asJpeg()` 先執行 `ImageBitmap.close()`，再讀取 `bitmap.height`；關閉後寬高可能變為 0。因而即使已修正題庫索引尺寸，仍會出現 `P31-017`、`P31-024` 等「圖片尺寸變動」錯誤。
- 現在 **在關閉影像前保存輸出 JPEG 的正確寬高**；配題尺寸與 JPEG 輸出統一使用相同的最大像素寬度及四捨五入規則，並支援無 `createImageBitmap` 的圖片解碼備援。
- 合併前預先取得每位學生實際要嵌入的 JPEG 及其尺寸；若歷史試卷有舊版尺寸資訊，會在畫入 PDF 前重新驗證並重新排版整份試卷，維持原題與題號一致；不會默默刪題或超出 A4。每位學生完成後釋放 JPEG 快取，降低整班合併時的記憶體占用。
- 一般「雙頁配題」也統一尺寸量測、縮放與 JPEG 輸出算法，避免另一條路徑出現同類錯誤。
- 相關測試：`node tests/fixed-pages.test.cjs`、`node tests/batch-geometry.test.cjs`、`node tests/image-conversion.test.cjs`。其中批次回歸測試現在會執行**真正的 JPEG 轉換程式**，模擬 `ImageBitmap.close()` 後寬高歸零，而非把轉換步驟以假資料略過。GitHub Actions 會在後續提交時執行三者。
